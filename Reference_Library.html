APPENDIX 4.1

Introduction to XML

XML fundamentals, validation and schema design patterns

Create → Check → View

Create an XML document in NetBeans, save it, check well-formedness, then open it in a browser. A browser tree is not proof of DTD/XSD validity.

Two contracts

DTD defines the document structure; XSD defines structure and supports typed values. Create separate .dtd and .xsd files.

Schema design patterns

Russian Doll: one global root with local declarations. Salami Slice: global elements are reusable. Venetian Blind: one global root with reusable named types and groups.

APPENDIX 4.2

XML Schemas

Types, occurrence rules and restrictions

Simple vs complex

Simple elements contain text only; complex elements may contain children or attributes. Text plus attributes uses simpleContent and extension.

Sequence · Choice · All

Sequence follows the declared order; choice selects an alternative; all allows children in any order (XSD 1.0 occurrence restrictions apply).

Data types and attributes

xs:string, xs:integer, xs:decimal, xs:boolean, xs:date, xs:ID, xs:IDREF and xs:IDREFS. Attributes can be required or optional.

Restrict a type

Use simpleType and restriction with facets such as enumeration, pattern, minInclusive or maxInclusive.

APPENDIX 4.3

Exploring XSLT

Preview for Part C • not required for Part A

Template → Output

xsl:template matches source nodes; xsl:value-of outputs a selected value.

Repeat → Sort → Filter

xsl:for-each processes multiple nodes; xsl:sort orders output; xsl:if tests a condition.

Choose → Apply → Copy

xsl:choose uses when/otherwise; apply-templates delegates to matching templates; copy is shallow and copy-of is deep.
